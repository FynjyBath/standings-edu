# Standings EDU

Сервис для ведения таблиц результатов учеников: собирает решения с
Codeforces, informatics.msk.ru, ACMP, ejudge и Moodle, поддерживает ручные
таблицы оценок («кондуиты») и показывает всё это красивыми таблицами в вебе.

Как это работает, в двух словах:

```
data/ (ученики, группы, контесты)  →  cmd/generate  →  generated/ (готовые JSON)  →  cmd/server  →  веб-страницы и API
```

- **`data/`** — исходники, которые вы редактируете (руками или через админку);
- **`cmd/generate`** — опрашивает источники и собирает таблицы;
- **`cmd/server`** — показывает готовые таблицы; после перегенерации новые
  данные подхватываются автоматически, без перезапуска.

---

## Быстрый старт

```bash
# 1. Заготовки данных из примеров
mkdir -p data/groups/group_example data/credentials
cp data_example/students_example.json data/students.json
cp data_example/contests_example.json data/contests.json
cp data_example/groups/group_example/group_example.json data/groups/group_example/group.json
cp data_example/groups/group_example/contests_example.json data/groups/group_example/contests.json

# 2. Креды для админки (логин/пароль Basic Auth)
cp data_example/credentials/admin_credentials_example.json data/credentials/admin_credentials.json
# (отредактируйте логин/пароль!)

# 3. Генерация и запуск
go run ./cmd/generate
go run ./cmd/server
```

Откройте:

- `http://localhost:8080/standings` — входная страница;
- `http://localhost:8080/standings/group_example` — таблицы группы;
- `http://localhost:8080/standings/admin` — админка (Basic Auth).

Сервер при старте сам создаёт недостающие runtime-файлы и каталоги
(`generated/`, пустые `students.json`/`contests.json` и т. п.), существующее не
перезаписывает.

Генерацию имеет смысл повесить на cron/systemd-timer (например раз в 5 минут) —
кнопка «Сгенерировать» в админке делает то же самое вручную.

## Данные: что где лежит

| Файл | Что хранит |
|---|---|
| `data/students.json` | ученики: id, ФИО, публичное имя, аккаунты на сайтах |
| `data/contests.json` | глобальные определения контестов |
| `data/manual_tables.json` | оценки глобальных кондуитов (contest_id → таблица) |
| `data/groups/<slug>/group.json` | группа: название, состав, доступы (`accesses`), конфиг оценок |
| `data/groups/<slug>/contests.json` | контесты группы (ссылки на глобальные и/или inline) |
| `data/groups/<slug>/manual_tables.json` | оценки inline-кондуитов группы |
| `data/groups/<slug>/grades_manual.json` | ручные оценки столбцов («в формулу») |
| `data/credentials/*` | креды источников и админки (в git не попадают) |
| `data/student_intake.json` | входящие анкеты учеников |
| `generated/` | результат генерации (переписывается, руками не править) |

Всё, что в `data/`, можно править и руками, и формами админки — они читают и
пишут одни и те же файлы. После правок нужно перегенерировать.

## Источники результатов (сайты)

Ученик привязывается к сайту через `accounts` в `students.json`:
`{"site": "codeforces", "account_id": "tourist"}`.

| Сайт | Креды (в `data/credentials/`) | Время посылок | Особенности |
|---|---|---|---|
| `codeforces` | `codeforces_credentials.json` — опционально (key/secret для приватных групп/gym) | есть | без ключа работает анонимно |
| `informatics` | `informatics_credentials.json` — обязателен (username/password, опц. `base_url` — какое зеркало показывать в ссылках) | есть | зеркала msk/mccme считаются одним сайтом; инкрементальный кэш посылок; битые записи «спасаются» дроблением страниц |
| `acmp` | не нужны | нет | только «решено/попытки», окна и дорешка не применяются |
| ejudge (любые экземпляры) | `ejudge_credentials.json` — массив экземпляров | есть | `ejudge_id` экземпляра = имя сайта в аккаунтах; нужен привилегированный API-ключ |

Формат ejudge-кредов:

```json
[{ "ejudge_id": "kodu", "base_url": "https://ej.kod-u.ru",
   "api_key": "AQAA...", "contest_keys": { "25408": "AQAA..." } }]
```

Если файла кредов нет — источник просто отключается (с предупреждением в
логе), генерация не падает. Битый файл — ошибка конфигурации, генерация
останавливается.

## Контесты

Контест — это одна таблица на странице группы. Два типа (`source_type`):

- **`tasks`** (по умолчанию) — вы перечисляете ссылки на задачи, сервис сам
  собирает решения учеников;
- **`provider`** — готовую таблицу строит провайдер (см. ниже).

### Ссылки и inline

В `data/groups/<slug>/contests.json` каждый элемент — либо **ссылка** на
глобальный контест, либо **полное определение прямо в группе** (inline):

```json
[
  { "id": "contest_basics", "update": true },
  { "id": "oneoff", "update": true, "title": "Разовый контест",
    "score_system": "ioi", "source_type": "provider",
    "provider": "codeforces_contest", "provider_config": { "contest_id": 1711 },
    "subcontests": [] }
]
```

Элемент считается inline, если содержит `title`, `score_system`,
`source_type`, `provider`, `provider_config`, `subcontests` или `materials`.
`update: false` замораживает таблицу (не пересобирается при генерации).

### Задачи и «разворачивание» ссылок

В `tasks`-контесте элементом списка задач может быть:

- ссылка на **одну задачу** (Codeforces, informatics, ACMP, ejudge);
- ссылка на **контест Codeforces целиком** (`/contest/<id>`, `/gym/<id>`,
  `/group/<gid>/contest/<id>`) — развернётся во все его задачи;
- ссылка на **сборник informatics** (`…/view.php?id=<N>` без `chapterid`) —
  развернётся в задачи по оглавлению; **скрытые задачи сборника**
  (затемнённые) в публичной таблице не показываются, но видны от роли «Наблюдатель»
  (помечены 🔒);
- ссылка на **контест ejudge** (`new-client?contest_id=N` без `prob_id`) —
  развернётся в его задачи.

### Поведенческие параметры

Задаются в глобальном определении (для всех групп) и/или в записи группы
(переопределение — приоритетнее):

| Параметр | Что делает |
|---|---|
| `score_system` | `edu` — плюсики, `ioi` — баллы 0–100 (в ячейках `50 (70)`: балл в окне + дорешка) |
| `table_name` | вкладки сводной таблицы (строка или список) |
| `start_time` / `end_time` | окно контеста: в зачёт — посылки в окне, позже — дорешка в скобках; до старта сервер прячет ссылки на задачи |
| `freeze` | заморозка: `"1h"`, `"30m"`, `"all"`, `"none"`; публично видны посылки только до `end − freeze`, полная версия — от роли «Наблюдатель» |
| `zero_penalty` | (ioi) штраф за каждую задачу без баллов, появляется колонка «Штраф» |
| `summary_total_only` | в сводной — одна колонка суммы вместо задач (+ `short_name` для узкого заголовка) |
| `hidden` | скрыть контест у школьников (виден от роли «Наблюдатель», в оценках учитывается) |
| `materials` | список ссылок «Полезные материалы» под заголовком |

Окна/заморозка работают для сайтов с временем посылок (CF, informatics,
ejudge); ACMP не фильтруется.

Пометка «Зачтено»: задача, решённая статусом «зачтено» (не полный OK),
показывается плюсом с жёлтой рамкой. У informatics рамка — на «ЗАЧТЕНО», у
ejudge — на «OK» (а «ОЖИДАЕТ ПОДТВЕРЖДЕНИЯ» — плюс без рамки).

Плюсы/баллы в ячейках — это ссылки на посылки ученика по задаче (informatics).

## Провайдеры (`source_type: "provider"`)

### `codeforces_contest`

```json
"provider_config": { "contest_id": 1711, "show_unofficial": true }
```

Таблица контеста CF по участникам группы; дорешка — в скобках. Для gym —
`contest.standings`, для публичных — через `contest.status`.

### `html_table_import`

Импорт готовой HTML-таблицы с чужой страницы:

```json
"provider_config": { "page_url": "https://…", "columns": ["place","name","task","task"], "auto_find": true }
```

Сопоставление строк с учениками — по ФИО.

### `moodle_grades` — оценки из Moodle

Берёт оценки из журнала курса Moodle по ссылке на любую оцениваемую
активность (тест, задание…):

```json
"provider_config": {
  "activity_url": "https://kurs.kod-u.ru/mod/quiz/view.php?id=5",
  "moodle_group": "10А",        // опц.: группа Moodle (название или id)
  "show_all": false,             // true: показать всех пользователей курса
  "display": "percent"           // "percent" (0–100, с заливкой) или "raw"
}
```

Креды — `data/credentials/moodle_credentials.json`:
`{"base_url": "https://kurs.kod-u.ru", "token": "…"}` (токен веб-сервиса,
сервис «Moodle mobile web service») либо `username`/`password`. Сопоставление
учеников — по ФИО (порядок слов не важен). Точная оценка «9,2 из 10» — в
колонке «Статус». Один запрос журнала на курс за генерацию (кэшируется в
рамках запуска).

### `manual_table` — кондуит (ручной ввод оценок)

Таблица, которую заполняют руками: строки — ученики (по ФИО), колонки —
задачи. Семантика ячеек: пусто — не сдана, `1`/`+`/любое число ≠ 0 — сдана,
`0`/`±` — попытка. `score_system: edu` показывает плюсики, `ioi` — числа.

```json
"provider_config": { "task_count": 10, "show_all": false }
```

Оценки хранятся **отдельно от определения**: в `data/manual_tables.json`
(глобальные кондуиты) или `data/groups/<slug>/manual_tables.json` (inline).

Заполнение — в админке (форма контеста: режимы «Заполнить в форме» —
сетка с учениками группы, и «Вставить из Google Таблиц» — копипаста TSV) или
доступом с правом `konduit.fill` (см. ниже). Вставка блока из буфера работает прямо в ячейки
сетки.

**Общий кондуит на несколько групп:** один глобальный `manual_table`-контест,
добавленный по ссылке в несколько групп, хранит одну таблицу — оценки ученика
автоматически синхронизируются между группами. Каждая группа видит и
редактирует только своих учеников.

## Страницы

| Адрес | Что показывает |
|---|---|
| `/standings` | входная страница; с правом `view.directory` (глобальный доступ) — каталог групп со ссылками |
| `/standings/<slug>` | таблицы группы: доска почёта + контесты |
| `/standings/<slug>/summary` | сводная: все контесты в одну таблицу, вкладки по `table_name` |
| `/standings/<slug>/grades` | оценки группы (если настроены) |
| `/standings/<slug>/contest?id=…` | таблица одного контеста: листалка соседей, фильтр по имени, экспорт этой таблицы |
| `/standings/<slug>/participants?token=…` | статистика участников (право `view.participants`) |
| `/standings/<slug>/student?id=…&token=…` | профиль ученика (право `view.participants`) |
| `/standings/<slug>/panel` | вход по логину и паролю (доступ группы) |

- **Доска почёта** — сколько различных задач полностью решено на сайтах
  группы (по всем задачам сайта, не только из контестов), сортировка по
  видимой сумме.
- **Профиль ученика** — решено всего/сегодня, посылки за 7/30 дней, метрики
  скорости, график активности за 90 дней, лента посылок (CF + informatics).
- Шапки таблиц и колонки с учениками закрепляются при прокрутке.
- **Страница контеста** — клик по названию контеста в сводной открывает
  отдельную страницу только с этой таблицей: грузится мгновенно, ссылку можно
  переслать, соседние контесты листаются кнопками. Экспорт в Excel с неё даёт
  книгу из одного листа (`?contest=<id>` у `export.xlsx`).

### Объединённые группы

`group.json` с `member_groups: ["group_a", "group_b"]` — страница собирается
на лету из таблиц групп-участниц: контесты с одинаковым id сливаются в одну
таблицу с пересчётом мест, доска почёта объединяется. Управляется из админки
(раздел «Объединённые группы»), там же можно скрывать отдельные контесты
объединения.

### Ссылки ejudge в режиме судьи

На страницах для преподавателей (под доступом с правами просмотра)
задачи ejudge открываются **в судейском интерфейсе**: клиентская ссылка
`…/new-client?contest_id=N&prob_id=M` заменяется на `…/new-judge?contest_id=N`
(судейский вход адресуется контестом). Замена только на показ — в данных и в
сопоставлении задач с посылками (`normalized_url`) остаётся клиентская форма,
перегенерация не нужна. Ученикам ссылки остаются клиентскими.

### Зеркала informatics

У informatics два домена одного сайта: `informatics.msk.ru` и
`informatics.mccme.ru`. Рабочее зеркало задаётся в `base_url` в
`data/credentials/informatics_credentials.json`, и **любая добавленная ссылка
сразу приводится к нему** — вставлять можно какую угодно (msk/mccme, `www`,
`http`), в данных окажется настроенная. Приведение работает на всех путях
добавления: форма контеста в админке, управление контестами группы,
материалы, адреса внутри `provider_config`, импорт бандла и сырой JSON-редактор.

Серверу путь к кредам задаётся флагом `-informatics-creds-file` (по умолчанию
`./data/credentials/informatics_credentials.json`); файла нет или `base_url`
пуст — ссылки сохраняются как введены. Сопоставление задач с посылками от
домена не зависит (`normalized_url` канонизируется отдельно), так что старые
данные со «смешанными» доменами продолжают работать.

## Оценки («в формулу»)

Опциональная таблица оценок группы: поле `grades` в `group.json`. Итог =
взвешенное среднее столбцов (каждый 0–10). Столбцы:

- **`type: "table"`** — считается из сводной вкладки `table_name`:
  `metric` = `plus`|`score`, нормировка `normalize` = `"max"` (топ по каждому
  контесту = 10) | `"total"` (все задачи = 10) | число; опц. `upsolving` (0–1)
  — коэффициент учёта дорешки;
- **`type: "manual"`** — ручные оценки, хранятся в `grades_manual.json`,
  заполняются в админке («Оценки» у группы) или доступом с правом `grades.manual`.

Оценки считаются при генерации — изменения видны после ближайшего
`generate`.

## Доступы: права, ссылки и учётки

Доступ к группе — это **список записей** в её `group.json` (`accesses`). Каждая
запись: название, способ входа, набор прав и выключатель. Ролей больше нет —
права отмечаются галочками, а прежние роли остались как **пресеты**.

| Право | Что даёт |
|---|---|
| `view.unfrozen` | размороженные таблицы (полные версии замороженных) |
| `view.hidden` | скрытые контесты и задачи |
| `view.task_links` | ссылки на условия, даже если ученикам они выключены |
| `view.participants` | статистика участников и профили учеников |
| `view.export` | выгрузка в Excel |
| `view.judge_links` | ejudge открывается в режиме судьи (`new-judge`) |
| `grades.manual` | выставлять ручные оценки |
| `grades.config` | настраивать таблицу оценок (столбцы, веса, метрика, нормировка, дорешка) |
| `konduit.fill` / `konduit.create` | заполнять / создавать кондуиты |
| `flags.review` | размечать флаги нечестности |
| `contests.manage` | добавлять, убирать и настраивать контесты группы |
| `contests.inline` | создавать и править свои (inline) контесты |
| `view.directory` | каталог групп на `/standings` (только у глобальных доступов) |

Пресеты: **Наблюдатель** (весь просмотр), **Жюри** (+ оценки, кондуиты, флаги),
**Админ** (+ контесты группы), **Куратор** и **Только каталог** (глобальные).

**Способы входа.** Либо ссылка с токеном (`/standings/<slug>?token=…`), либо
логин и пароль: для доступа группы — на `/standings/<slug>/panel`, для
глобального — на `/standings/login` (оттуда сразу в каталог групп). Браузер
спросит учётку (Basic Auth), сервер выдаст куку сессии на 12 часов и дальше
работают обычные адреса;
на странице появляется кнопка «Выйти». Кука подписана секретом
`data/credentials/panel_secret.json` и содержит отпечаток записи доступа:
смена пароля или токена мгновенно обесценивает выданные сессии. Права **всех**
подтверждённых доступов объединяются.

Токены и пароли лежат в `group.json` открытым текстом (не переиспользуйте
важные пароли) и вырезаются из бандла экспорта вместе с ключом `accesses`.

**Глобальные доступы** (`data/credentials/global_accesses.json`, редактируются
на `/standings/admin`) устроены так же, но действуют либо на все группы, либо
на выбранные галочками. Ими же выдаётся каталог: `/standings` с правом
`view.directory` показывает карточку на группу. В карточке «Перейти» — обычный
адрес группы (его же дают ученикам, а вошедшему преподавателю он открывает
группу сразу с его правами: доступ уже подтверждён сессией, токен в адресе не
нужен), а следом — ссылки с токеном, по одной на каждый доступ-ссылку,
подписанные его названием и с кнопкой «Копировать». Токен-доступов нет — в
карточке остаётся только «Перейти». Без права каталога — обычный приветственный
экран; неверный токен факт существования каталога не раскрывает.

### Страницы под доступом

| Адрес | Право | Что |
|---|---|---|
| `/standings/<slug>` | — | таблицы группы; вид зависит от прав `view.*` |
| `/standings/<slug>/panel` | — | дверь входа по логину и паролю в группу, дальше — та же страница группы |
| `/standings/login` | — | дверь входа для глобальных доступов, дальше — каталог групп |
| `/standings/<slug>/manage/grades` | `grades.*` | столбцы оценок и ручные оценки |
| `/standings/<slug>/manage/contests` | `contests.manage` | управление контестами группы |
| `/standings/<slug>/participants` | `view.participants` | статистика участников |
| `/standings/<slug>/student?id=…` | `view.participants` | профиль ученика (+ разметка флагов при `flags.review`) |
| `/standings/<slug>/jury-konduit?id=…` | `konduit.fill` | редактор кондуита |
| `/standings/signout` | — | выход (гасит куку сессии) |

У inline-контестов, создаваемых доступом группы, **окно (начало и конец)
обязательно** — в отличие от админки. Provider-контесты окно не используют.

**Старые группы** (`group_secret_token` + `panel_access`) продолжают работать:
пока списка `accesses` нет, старые поля читаются как доступы «Наблюдатель»,
«Жюри», «Админ». Первое сохранение в админке переносит их в `accesses` (токен и
пароли сохраняются) и убирает старые поля.

### Журнал действий

Входы по логину и паролю и все изменения пишутся в `data/logs/audit.log` —
по строке JSON на событие, с ротацией в `.1` при 5 МБ. Смотреть:
`/standings/admin/logs` (кнопка «Посмотреть журнал» в админке). Чтение страниц
не логируется.

Изменения данных (кондуиты, оценки, состав контестов) попадают в таблицы
после ближайшей генерации.

## Админка (`/standings/admin`)

Basic Auth: `data/credentials/admin_credentials.json`
(`{"login": "...", "password": "..."}`).

- **Действия:** «Сгенерировать все таблицы»; «Сбросить кеш»
  informatics/codeforces (за неделю/месяц/год/всё; всех / ученика / группу);
  экспорт/импорт; intake-merge.
- **Ученики** — CRUD учеников и аккаунтов, кнопка «Профиль» у каждого.
- **Контесты** (`/standings/admin/contests`) — конструктор контестов; для
  `moodle_grades` и `manual_table` есть удобные формы (не нужно писать JSON); в
  списках показывается вид контеста («задачи», «Moodle», «кондуит»…). Порядок
  списка меняется стрелками ↑↓ у строки или кнопкой **«⇅ Отсортировать по id»**
  (числа сравниваются как числа: `week_9` раньше `week_10`). Это порядок в
  `contests.json` и в выпадашках «добавить в группу»; на таблицы групп он не
  влияет — там свой порядок.
- **Группа** — состав, короткое название, ссылка на форму регистрации, доступы,
  контесты группы (ссылки/inline, порядок, переопределения: окно, заморозка, вкладки,
  «показывать» и т. д.), аккаунты, оценки. Есть **регистрация списком ФИО**
  (по одному в строке): для новых ФИО создаётся пустая запись ученика, для
  существующих — дописывается группа; сначала «Пробный запуск» показывает, что
  произойдёт, и предупреждает о неоднозначных совпадениях (несколько учеников
  с одинаковым ФИО) и повторах.
- **Объединённые группы** — создание/состав/скрытие контестов.
- **JSON-редактор** (`/standings/admin/files`, кнопка из админки) — прямое
  редактирование data-файлов («люк» на случай, когда формы не хватает). Живёт
  отдельной страницей: редактор ACE весит ~450 КБ, и на самой админке он не
  грузится.
- Блок «Результат последнего действия» — полный вывод команды.

Записи в data-файлы сериализуются (одновременные правки не теряются), файлы
пишутся атомарно.

### Экспорт / импорт (перенос между серверами)

«Экспорт» собирает JSON-бандл: ученики, группы (с выбором по каждой группе:
участники и/или контесты), глобальные контесты, **оценки кондуитов и ручные
оценки**. «Импорт» дописывает бандл на целевом сервере: существующее не
перезаписывается, а оценки (кондуиты и ручные) **сливаются по максимуму** —
по каждой ячейке берётся лучший результат из двух серверов. Повторный импорт
безопасен. Токены групп переносятся по галочке. Credentials не экспортируются
— их кладут на сервер руками.

## Анкеты учеников (intake)

`POST /api/rpc`, метод `student_intake.submit`:

```json
{ "jsonrpc": "2.0", "id": 1, "method": "student_intake.submit",
  "params": { "full_name": "Иванов Иван", "codeforces": "handle", "group": "group_a" } }
```

Анкеты копятся в `data/student_intake.json` и попадают в базу только после
merge (в админке: staging → «Пробный запуск» (dry-run с таблицей «кто куда») →
merge; или `go run ./cmd/merge_students -write`). Сопоставление — по ФИО,
повторная анкета обновляет аккаунты.

Приём анкет можно закрыть токеном: `data/credentials/intake_credentials.json`
(`{"token": "…"}`); тогда запрос должен содержать заголовок `X-Intake-Token`
или `params.token`.

## Эксплуатация

- **Генерация по расписанию:** cron/systemd-timer на `bin/generate`; флаг
  сервера `-generate-interval 5m` показывает в футере обратный отсчёт до
  следующего обновления (0 — скрыть).
- **Кэши источников** — в `generated/cache/` (informatics и codeforces качают
  инкрементально). «Сбросить кеш» в админке заставляет перечитать аккаунты
  с нуля.
- **Favicon'ы** (`web/static/favicon*`, `apple-touch-icon.png`) в git **не
  отслеживаются** — каждый сервер держит свои; при обновлении кода они не
  затираются. На новый сервер их копируют руками (scp).
- **Бинарники:** после обновления кода пересоберите оба —
  `go build -o bin/server ./cmd/server && go build -o bin/generate ./cmd/generate`.
  Шаблоны (`web/templates`) и статика читаются с диска, для их правок
  пересборка не нужна.

Основные флаги:

```bash
go run ./cmd/generate -data-dir ./data -generated-dir ./generated -group <slug> -parallelism 8
go run ./cmd/server   -addr :8080 -data-dir ./data -generated-dir ./generated -generate-interval 5m
go run ./cmd/create_group -slug group_10a -name "Группа 10А"
go run ./cmd/merge_students -dry-run   # или -write
```

## Для разработчиков

Структура:

- `cmd/` — точки входа (generate, server, create_group, merge_students);
- `internal/domain/` — модели и нормализация (URL задач, имена, слияние групп);
- `internal/source/` — интеграции: сайты (`SiteClient`), провайдеры
  (`ContestProvider`), реестр;
- `internal/standings/` — pipeline генерации (builder, профили учеников);
- `internal/storage/` — чтение `data/`, запись `generated/`;
- `internal/httpapi/` + `internal/web/` + `web/` — HTTP, шаблоны, статика;
- `internal/migrate/` — экспорт/импорт;
- `internal/studentintake/` — анкеты и merge.

**Новый сайт задач:** реализовать `SiteClient`
(`FetchUserResults`, `MatchTaskURL`, `SupportsTaskScores`) в
`internal/source/`, зарегистрировать в `cmd/generate/main.go`
(`registry.RegisterSite`). `MatchTaskURL` должен узнавать ссылки задач —
иначе решения не сопоставятся.

**Новый провайдер:** реализовать `ContestProvider`
(`ProviderID`, `BuildStandings`), зарегистрировать
(`registry.RegisterProvider`), добавить option в селект провайдеров в
`web/templates/contest_form.partial.html`.

Чеклист перед выкаткой:

```bash
gofmt -l . && go vet ./... && go test ./...
go run ./cmd/generate -group <тестовая_группа>
go run ./cmd/server   # и глазами проверить страницы
```

## FAQ

**На странице нет таблиц.** Не запускалась генерация, или у группы нет
контестов с `update: true`.

**Оценки/кондуит поменяли, а на странице по-старому.** Всё, что влияет на
содержимое таблиц, применяется при генерации — дождитесь следующей или
нажмите «Сгенерировать».

**У ученика подозрительно мало решённых задач.** Откройте его профиль в
админке и сравните с сайтом; при расхождении — «Сбросить кеш» по ученику и
перегенерировать.

**Ссылка с токеном утекла ученикам.** В админке группы, в блоке «Доступы»,
нажмите «Новый токен» у этой записи (или выключите её) и сохраните — старая
ссылка перестанет работать сразу. Кто и что делал, видно в журнале
(`/standings/admin/logs`).

**Нужны ли креды всех источников?** Нет: без файла кредов источник просто
отключается. Обязательны только `admin_credentials.json` (для админки) и
креды тех сайтов, которые вы реально используете.
